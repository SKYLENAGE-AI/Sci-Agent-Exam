Smilei is an open-source electromagnetic particle-in-cell code for kinetic plasma simulation. This task uses a benchmark-style one-dimensional laser-plasma diagnostic with a perpendicular magnetic field and asks the agent to orchestrate catalog, namelist, HDF5, FFT, and validation tools.

## Scientific Framing

This is a Tool Orchestration task because the final verdict is not recoverable from one file or one tool call. A correct workflow must query a local catalog, join it to the diagnostic contract, parse the Smilei namelist to recover laser and magnetic-field scales, inspect and load HDF5 probe/field diagnostics, compute contract-defined FFT band powers, validate polarization phase and charge-channel coupling, and reconcile all handoffs. Wrong candidate selection, wrong HDF5 schema, wrong FFT window, wrong laser-frequency normalization, wrong charge-channel treatment, or using field energy as the primary harmonic signal changes the answer or violates a required invariant.

## Reference Workflow

1. `sqlite3` enumerates accepted `laser_plasma_harmonics` candidates in the `harmonic_probe` diagnostic family and reads the paired diagnostic contract. Candidate rows provide harmonic order and validation thresholds; the contract provides dataset names, signal group, analysis window, spectral bands, window function, detrending, and power/phase conventions.
2. Python stubs execute the Smilei-style namelist enough to record `Main`, `ExternalField`, `LaserPlanar1D`, `Species`, `DiagProbe`, and `DiagFields` keyword arguments. The reference recovers laser omega0, laser amplitude, perpendicular Bz, timestep, density, and diagnostic fields from the deck.
3. `h5dump -n` inspects the selected probe and field HDF5 files before numerical array loading. `h5py` then loads the contract-named time, iteration, and signal datasets.
4. The probe `Ey` signal is detrended and windowed according to the diagnostic contract. A real FFT is converted to angular frequency normalized by the namelist laser frequency.
5. Each accepted candidate harmonic is evaluated by band peak frequency, harmonic/fundamental band-power ratio, peak prominence, `Rho`-to-`Ey` harmonic-band charge coupling, and complex `Ey`/`Bz` phase lag. Exactly one candidate is carried forward.
6. The field HDF5 electromagnetic-energy scalar is written as a separate consistency handoff. The final report and figure interpret the harmonic spectrum, phase relation, magnetization, and limitations.

## Key Parameters And Consequences

- Catalog candidate: choosing a rejected, decoy, or wrong accepted harmonic changes the harmonic order and thresholds.
- Diagnostic contract: hardcoding the visible schema, FFT window, or analysis interval fails hidden contract-shift reruns.
- Laser frequency: using raw FFT frequency instead of omega/omega0 shifts harmonic order.
- Windowing and detrending: using the full trace or a different spectral window changes band powers and prominence.
- Polarization phase: ignoring the complex `Ey`/`Bz` phase can accept a spectral peak that does not satisfy the magnetized diagnostic rule.
- Charge coupling: treating the charge-density channel as optional, or computing it with a different band/window than `Ey`, can accept a branch without the required plasma response.
- Field energy: using electromagnetic energy as the primary harmonic observable can produce a plausible-looking but scientifically wrong result.
- Invalid data handling: missing probe fields, incompatible row counts, nonfinite signals, and zero validated candidates must stop rather than emit a final answer.

## Common Failure Modes

- Reads HDF5 arrays directly and skips SQLite catalog/contract lookup.
- Hardcodes the visible time-axis or signal-group names instead of using the diagnostic contract.
- Normalizes harmonic order by plasma frequency, raw bin index, or sample rate rather than namelist laser omega0.
- Uses a single FFT bin or unwindowed peak instead of the contract-defined band-power calculation.
- Selects the strongest spectral peak without checking phase lag, prominence, charge coupling, and catalog thresholds.
- Reports harmonic generation from field-energy modulation alone.
- Submits a plausible narrative whose code cannot rerun on perturbed or schema-shifted mounted data.
